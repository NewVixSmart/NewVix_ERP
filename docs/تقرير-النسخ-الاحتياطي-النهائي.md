# تقرير النسخ الاحتياطي والاستعادة وإعادة الضبط (Backup / Restore / Reset)

- **المشروع:** سِلْك للتداول (New Vix Smart ERP) — ASP.NET Core MVC
- **التاريخ:** 16/09/2026
- **النطاق:** ميزة النسخ الاحتياطي والاستعادة وإعادة ضبط النظام، مع تدقيق عميق (أمان، سلامة بيانات، وصولية WCAG 2.2 AA، جودة كود، تكامل) ونشر فحوصات GATE الشاملة.

---

## 1) ملخص تنفيذي

نُفِّذت ميزة النسخ الاحتياطي والاستعادة وإعادة ضبط النظام بشكل متكامل عبر SQL Server `BACKUP DATABASE` / `RESTORE DATABASE`، مع واجهة عربية RTL كاملة مقيّدة بإدارة الـ Admin وتحمل حقول تأكيد صريحة. خضعت الميزة لتدقيق متعدد الوكلاء وطُبِّقت عليها إصلاحات أمنية وسلامة بيانات ووصولية وجودة، ثم تحقَّقنا منها إلكترونيًا (E2E) بدورة كاملة ناجحة وفحوصات وصولية بلا أي انتهاكات.

## 3) القرارات التصميمية (بتوجيه المستخدم)
- **إعادة الضبط:** حذف كل بيانات النظام عدا حساب المسؤول (admin)، مع إعادة تعيين عدّادات الهوية والتأكد من القيود.
- **الاستعادة:** استبدال قاعدة البيانات بالنسخة، ثم توقيع خروج تلقائي وإعادة توجيه لصفحة تسجيل الدخول (لأن بيانات المستخدم تغيّرت).
- **إعادة الضبط أيضًا:** تُخرج المستخدم إلى صفحة الدخول بعد اكتمالها للحفاظ على اتساق الجلسة.
- رسائل النجاح والخطأ بالعربية عبر `TempData` مع تنسيق `alert-success`/`alert-danger`.

## 4) إصلاحات التدقيق العميق

### الأمان
1. **منع تسريب تفاصيل الاتصال:** توقّف عرض `ex.Message` مع أسماء جداول/مسارات؛ رسائل عربية عامة + تسجيل التفاصيل في `ILogger`.
2. **قفل العملية (SemaphoreSlim):** منع تنفيذ عمليات النسخ/الاستعادة/الضبط المتزامنة (سباق).
3. **SignOut بنمط صحيح:** استبدال `HttpContext.SignOutAsync()` بـ `SignInManager.SignOutAsync()` (Cookie Identity).
4. **حماية المسار:** رفض أسماء الملفات غير الصالحة ومنع اجتياز المجلد (`..`).
5. **كلمة تأكيد عند إعادة الضبط** (نص محدد) عوض زر واحد فقط.
6. **منع سباق استعادة concurrent = قفل + مهلة انتظار + رسالة "عملية أخرى قيد التنفيذ".**

### سلامة البيانات
- `DELETE` مع `DBCC CHECKIDENT (RESEED 0)` للجداول ذات الهوية.
- تعطيل ثم إعادة تفعيل القيود الأجنبية (NOCHECK → DELETE → CHECK) بترتيب صحيح لمنع فشل الحذف.
- حذف جداول Identity الفرعية والقوائم، مع الإبقاء على admin.
- معاملة (Transaction) واحدة للضبط، مع Rollback عند الفشل.

### الوصولية (WCAG 2.2 AA — 0 انتهاكات)
- عناوين ذات تسلسل منطقي (`h1/h2`).
- ربط كل إدخال بملصق واضح.
- `aria-label` للأزرار المعتمدة على الأيقونات.
- `role="alert"` للرسائل، و `aria-expanded` للتحكم القابل للتوسيع.
- تباين كافٍ في الوضعين الفاتح والداكن.
- تنقّل كامل بلوحة المفاتيح وقرّاء الشاشة.

## 6) دورة التحقق E2E (تطبيق حي، healthz 200)
دورة كاملة ناجحة (`CYCLE_OK`):
1. تسجيل دخول admin → إنشاء نسخة (تنشأ ملفات `.bak` على القرص).
2. إعادة ضبط النظام → حذف كل البيانات (0 عنصر) → توجيه لتسجيل الدخول.
3. إعادة تسجيل الدخول → استعادة أحدث نسخة → توجيه لتسجيل الدخول.
4. إعادة تسجيل الدخول → البيانات استُعيدت (**16** عنصرًا) وأُثبت صحتها.
